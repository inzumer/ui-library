# 003 — Build and Distribution Strategy

## Status

Accepted

## Context

The library must distribute a package that:
- Is tree-shakable (ESM)
- Works in CommonJS environments (legacy bundlers)
- Ships TypeScript declarations
- Does not bundle React (peer dep)
- Has a clean, stable public API surface

## Decision

Use **Vite in library mode** as the build tool with dual output (ESM + CJS).

Build configuration:
- **Entry:** `src/index.ts` — single barrel, named exports only
- **ESM output:** `dist/es/` — used by modern bundlers and native ESM consumers
- **CJS output:** `dist/cjs/` — used by legacy Node and CommonJS bundlers
- **Type declarations:** generated by `vite-plugin-dts` into `dist/types/`
- **Externals:** `react`, `react-dom`, `react/jsx-runtime`
- **Source maps:** enabled for both outputs

`package.json` exports map:
```json
{
  "exports": {
    ".": {
      "import": "./dist/es/index.js",
      "require": "./dist/cjs/index.js",
      "types": "./dist/types/index.d.ts"
    }
  },
  "main": "./dist/cjs/index.js",
  "module": "./dist/es/index.js",
  "types": "./dist/types/index.d.ts",
  "sideEffects": false
}
```

`sideEffects: false` enables aggressive tree shaking in webpack and Rollup consumers.

## Consequences

**Benefits:**
- Dual output ensures compatibility with modern and legacy consumers
- `sideEffects: false` maximizes tree shaking — consumers only pay for what they import
- `vite-plugin-dts` co-generates declarations without a separate `tsc` step
- Single entry point simplifies consumer imports

**Tradeoffs:**
- Dual build increases CI time slightly
- CJS output may not benefit from tree shaking in all consumer setups
- `sideEffects: false` requires that the library has no top-level side effects (guaranteed by architecture rules)

**Limitations:**
- Does not support sub-path exports per component out of the box (e.g., `@inzumer/ui/Button`). Can be added later if needed.
- Monorepo migration would require splitting build configs per package.

## Alternatives Considered

- **Rollup directly:** More control but higher configuration complexity. Vite wraps Rollup with sensible library defaults.
- **tsup:** Simpler setup, popular for libraries. Rejected in favor of Vite to share config with the dev server and Storybook.
- **ESM-only output:** Simpler, but breaks compatibility with Jest (without transform) and some legacy consumers. Dual output preferred until ESM is truly universal.
- **Monorepo at MVP:** Deferred. When the library exceeds ~50 components or needs independent versioning, migrate to Turborepo or a similar tool.
